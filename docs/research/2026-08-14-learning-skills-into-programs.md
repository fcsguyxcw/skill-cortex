# 从经验学习技能并固化为程序：复用边界与研究重心

日期：2026-08-14  
状态：**历史讨论稿，已被替代**

> [!WARNING]
> 本文记录项目从 routing-only 向“轨迹产生新技能”纠偏时的中间结论，但仍把研究对象写成了“从轨迹创造新 Skill”。当前项目研究的是**用户已安装 Skill 在真实使用中的渐进部分程序化**。范围、术语、阶段和验收以[当前权威研究规范](2026-08-14-experience-guided-installed-skill-proceduralization.md)为准；本文不再作为实施依据。

## 结论

当前项目发生了范围漂移：`Router 与全量 metadata 的选择` 被放大成了主研究，但原始目标是研究 `经验如何被提炼、验证并固化成可执行技能，以及失败后如何恢复思考`。

两者有关联，但不是同一个问题：

- Router 解决“已有技能中，当前任务可能需要哪个”。
- 学习与程序化解决“什么经验足以成为一个可靠、可复用的新技能”。
- 新技能通过统一 registry 进入现有发现接口；Router 只是消费这个产物，不需要先被重新发明。

因此，Router 应降级为基础设施验收：首版沿用全量 description 或成熟检索方案，只做少量本地兼容检查；主研究改为“候选技能的编译、验证、晋升、监控、回退与修订”。

## 已有工作可以直接复用的结论

1. [Voyager](https://arxiv.org/abs/2305.16291) 已展示可持续增长的可执行代码技能库，以及利用环境反馈、执行错误和自验证改进程序。
2. [Memp](https://arxiv.org/abs/2508.06433v4) 已研究从轨迹提炼步骤级指令和脚本级抽象，并持续更新、纠正和废弃程序性记忆。
3. [Skill-Pro](https://arxiv.org/abs/2602.01869) 已把技能表示为激活、执行和终止条件，并使用验证门控维护技能池。
4. [SkillCraft](https://arxiv.org/abs/2603.00718) 已研究把原子工具组合成可执行技能、缓存并跨任务复用。
5. [SkillX](https://arxiv.org/abs/2604.04804) 已覆盖轨迹到多层技能、执行反馈修订和技能库扩展。
6. [HASP](https://arxiv.org/abs/2605.17734) 已把文本建议升级成会在特定状态触发并干预 Agent loop 的可执行 Program Functions。
7. [SkillGen](https://arxiv.org/abs/2605.10999) 已用成功与失败轨迹归纳可审计技能，并通过同实例的有技能/无技能对照验证净效果。
8. [SkillAdaptor](https://arxiv.org/abs/2606.01311) 已覆盖失败轨迹的步骤级归因、局部技能修订和显式验收。

所以，以下表述不能作为本项目的新颖性声明：

- Agent 能从轨迹学习技能。
- 技能可以写成代码或可执行程序。
- 技能可以有激活条件、执行步骤和终止条件。
- 技能可以依据反馈持续更新。

## 尚可作为研究问题的窄边界

一个更可检验、但仍需完整文献与产品检索后才能声称新颖的问题是：

> 通用 Agent Skills runtime 能否把重复轨迹编译成带版本、前置条件、后置条件和回退契约的受限程序；仅在保留集验证非劣后晋升；运行时一旦发现适用边界或不变量被破坏，就自动退回完整 LLM 推理，并把该反例用于局部修订或降级？

重点不再是“生成一个程序”，而是整个可信生命周期：

```text
任务轨迹
  -> 候选技能
  -> 受限程序 / DSL
  -> 保留集回放与净效果验证
  -> 版本化晋升
  -> Registry
  -> 现有技能发现接口
  -> 带守卫执行
  -> 边界违反 / 惊讶
  -> 回退完整推理
  -> 失败归因、修订或降级
```

这与“人类熟练化”的联系是：经验被组块化为低认知成本的程序；异常或惊讶重新唤醒显式控制；新反例触发重新巩固。该比喻用于指导机制，不作为生物学等价声明。

## Router 阶段应如何处理

不再做一个大规模“什么时候 Router、什么时候全量 metadata”的独立研究阶段。采用以下工程规则：

1. 默认继续使用当前全量 description / 原生渐进加载。
2. 把技能发现封装为稳定接口，学习系统只向 registry 写入标准产物。
3. 只有真实产品指标显示 prompt 预算、延迟或选择质量已不可接受时，才在接口后替换为成熟的本地检索或分层检索。
4. 本地只做 smoke test：新生成技能能被发现、相似技能不会明显混淆、无技能任务可拒绝选择、守卫失败会回退。
5. 不建立 300 例路由 Gold Set，不研发额外 Router LLM，不让路由实验阻塞主研究。

外部研究可以回答“这种方法通常是否有效”，但无法给出适用于本机技能目录、中文查询、模型缓存和实际价格的通用切换阈值。因此需要的是小规模集成验收，不是重新证明论文结论。

## 建议的新阶段划分

### Phase 0：基础设施验收

- 沿用现有技能发现方式。
- 定义统一 `SkillArtifact` 与 registry 接口。
- 用少量代表性任务确认新技能可发现、可加载、可拒绝和可回退。

### Phase 1：候选技能归纳

- 从成功和失败轨迹中提取重复子过程、前置条件、效果与失败边界。
- 首版限定一个可重放领域，不追求通用任意任务。

### Phase 2：受限程序编译

- 编译为有类型参数、权限清单、前后置条件的 DSL 或参数化脚本。
- 首版不允许任意自修改代码或不受约束的系统操作。

### Phase 3：验证与晋升

- 对独立保留任务做 paired replay：比较无技能、文本技能、程序技能。
- 同时统计修复、回归、成本和失败恢复率；只有净效果非劣才晋升。
- 保存版本、来源轨迹、验证证据和回滚点。

### Phase 4：运行时回退与再巩固

- 守卫、不变量或效果检查失败时，停止程序并恢复完整推理。
- 将首个可归因失败步骤作为反例，触发局部修订、重新验证或技能降级。

## Copy-ready 决策文本

> 路由不是本项目的主创新，而是学习所得技能的发现接口。首版复用现有全量 description 或成熟检索，只做本地兼容验收；研究资源集中在“轨迹归纳 -> 受限程序 -> 独立验证 -> 版本化晋升 -> 运行时回退 -> 反例修订”的可信技能程序化生命周期。

## 置信度与缺口

- 高置信：轨迹提炼、可执行技能、激活条件、持续修订均已有明确先行工作，不能整体声称新颖。
- 高置信：Router 不需要成为程序化研究的前置主阶段，稳定 registry/discovery 接口足以解耦。
- 中等置信：完整的“受限编译 + 独立晋升 + 运行时边界检测 + 自动回退重规划 + 反例再编译”组合仍可能存在未检索到的高度重叠工作。
- 在任何论文级新颖性声明前，仍需系统文献、开源产品与专利检索，并逐项制作 claim chart。
